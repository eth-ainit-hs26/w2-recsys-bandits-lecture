% ===== Frame 1. The first stage of Airbnb's search =====

% ===== Frame 2. Two networks and the nearest homes =====
% Say: The new first stage. One network turns the search, its location, the number of guests and the size of the
% area, into a list of numbers, at the moment of the search. A second network turns each home, its amenities,
% location and capacity, its past views, wishlists and reviews, into a list of numbers of the same length, once a
% day for every home, in a batch job the night before. [click] Picture every home as a point and the search as a
% point: the homes nearest to the search join the shortlist. In the first version "nearest" meant the highest inner
% product, as in our video store; the latest one uses the distance.

% ===== Frame 3. The value =====
% Say: Airbnb built it in three versions and A/B tested each one: first the two networks with the inner product;
% then the same with a clustered index, where the homes are grouped every day and only the groups nearest to the
% search are searched; then a larger network that uses the distance. [click] Together the three raised conversion
% by 0.31 percent, a relative change. That sounds small. Airbnb's paper calls it "a large portion of the team's
% annual goal", and its blog puts it on par with some of its largest machine learning improvements to search
% ranking in the past two years. [click] The same system now also picks the homes for promotional emails, where
% bookings rose by 2.3 percent, and the clustered index used about 16 percent less compute than the old first
% stage. The source is a preprint of January 2026 and Airbnb's blog of April 2025.
\begin{frame}{Three A/B tests, together +\abConv\% conversion}
  \begin{tikzpicture}[x=1mm, y=1mm]

         inner sep=1.5pt] (\vname) at (\vx,-4.5) {\vtext};}
